# 09 — Testing and QA

Every CRM and ERP phase lands with tests at each layer it touches. Nothing is
marked `DONE` in the [tracker](./README.md#phase-tracker) until these pass
locally and the repository's own checks (`pnpm turbo run typecheck lint test`)
are clean.

## How to run them

| Layer                    | Command                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| Domain rules             | `pnpm --filter @integr8/core test`                                                         |
| Screens (jsdom, axe)     | `pnpm --filter @integr8/operations-dom test`                                               |
| Translation parity       | `pnpm --filter @integr8/i18n test`                                                         |
| Database (real Postgres) | `pnpm --filter @integr8/db test:integration` (needs `DATABASE_URL` and the migrations run) |
| API (real Postgres)      | `pnpm --filter @integr8/api test:integration`                                              |

CI runs the integration suites against a Postgres service container.

## Manual checks before the pilot (phase L)

- Arabic: open each CRM screen with the language set to Arabic and check the
  layout mirrors, numbers and amounts read correctly, and email and phone stay
  left-to-right.
- Keyboard only: every CRM action reachable and the dialogs trap focus.
- Desktop right-click on lead rows and opportunity cards.
- The board at phone, tablet and desktop widths, in both languages.
- A dispatcher runs the MVP path by hand: lead → qualify → opportunity → convert → follow-up → mark won.
- Sales (S1): opportunity → quote → issue → open the customer link in a private window in English and in Arabic, print to PDF from both, accept with a name → convert → confirm at a store with too little stock → "to order" on the inventory overview → receive goods → re-reserve → create a job from the order → use the parts on it → complete the job → the order is delivered.
- Finance (B1): set the invoice settings → complete a job with parts → "Invoice this job" → issue → print to PDF in English and in Arabic → record a part payment from the invoice → the customer's account shows what is owed and on account → put the rest of a second payment against it → paid. Then from a delivered sales order: invoice what was delivered, credit one line, try to void (refused), take back an allocation.
