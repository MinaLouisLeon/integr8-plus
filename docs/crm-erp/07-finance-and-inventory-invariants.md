# 07 — Finance, inventory and purchasing invariants

The rules stock and purchasing keep, whatever the API or a screen does. Each
names where it is enforced. Built in E1 and E2, extended by sales in S1,
invoices and payments in B1, and the asset register in E3.

## Quantities and money

| Rule                                                                                                       | Where                                              |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Quantities are `numeric(20,4)` and travel as decimal strings (`"2.5"`); never JavaScript numbers           | schema, zod `decimalQuantitySchema`, UI formatting |
| Money is `numeric(20,4)` decimal strings in the company currency; tax rates are basis points (1400 = 14 %) | schema, zod, SQL arithmetic                        |
| Totals, tax and averages are computed in SQL `numeric` and rounded half-up to 4 places once, at the end    | repositories                                       |

## Stock

| Rule                                                                                               | Where                                                                       |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| The ledger (`erp_stock_movements`) is append-only; corrections are compensating movements          | grants (no update/delete), trigger                                          |
| Balances are a projection of the ledger, written only by the ledger's trigger                      | no grant on `erp_stock_balances` for the app role; trigger                  |
| Stock never goes negative at any location                                                          | `check (on_hand >= 0)` on the balance, under the row lock the trigger takes |
| A transfer moves stock out of one place and into another in one transaction, with one `posting_id` | inventory service                                                           |
| A posting happens once per `source_key` (receipt line, transfer key, phone action id)              | unique index                                                                |
| Only `stock_item` items have stock; services and non-stock items never appear in the ledger        | trigger                                                                     |
| Replaying the ledger reproduces every balance exactly                                              | `reconcile`, tested over 100 000 movements                                  |
| A stock count posts its variances as `count_adjustment` movements naming who posted it             | count service, audit log                                                    |

## Cost

| Rule                                                                                                                                              | Where                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Each stock item has one **weighted average unit cost** for the company (all locations)                                                            | `erp_items.average_unit_cost`                              |
| Only a goods receipt changes it: `new = (on_hand × old + received × unit_cost) ÷ (on_hand + received)`, computed in SQL under the item's row lock | receipt service                                            |
| A part used on a job records the average at that moment as its unit cost; later receipts never change it                                          | `erp_work_order_materials.unit_cost`, movement `unit_cost` |
| Costs are shown to seats that move stock or purchase (owner, admin, dispatcher), not to engineers or viewers                                      | API bodies                                                 |
| Purchasing is in the company currency only in E2; multi-currency purchasing waits for a conversion rule (PLAN §5 ERP-01)                          | API validation                                             |

## Purchasing

| Rule                                                                                                                  | Where                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `draft → approved → partially_received → received`, or `cancelled` from any open status; what was received stays      | `purchasing.ts`, `erp_purchase_orders_status_known`, `_approved_pairing`, `_cancelled_pairing`                                  |
| Only owners and admins approve; approving is audited with who and when; an empty draft is not approved                | `purchasing.approve`, `approved_by/at`, audit `purchase_order.approved`                                                         |
| An approved order's lines never change; only what was received moves                                                  | trigger `erp_purchase_order_lines_guard` (`erp_purchase_order_lines_frozen`)                                                    |
| Goods are received only against an approved order, never more than ordered on a line                                  | 409 `order_not_receivable`; `erp_purchase_order_lines_received_range` (422 `over_received`)                                     |
| Each stock-item receipt line posts one `receipt` movement, once, at the price received, folding into the average cost | `source_key = receipt-line:<id>`; `applyReceiptCost` under the item's row lock                                                  |
| Returns to a supplier are `return_to_supplier` movements reversing the receipt movement, never more than received     | `reversal_of`; `erp_goods_receipt_lines_returned_range` (422 `over_returned`); 409 `insufficient_stock` when the goods are gone |
| References are `PO-000001` onwards per company, never reused, never shared by two drafts                              | `assign_purchase_order_reference()` locks the company's counter row                                                             |
| Line, tax and order totals are derived, never typed; tax is a rate in basis points per line                           | SQL in `orderLines` / `orderTotals`, `erp_purchase_order_lines_tax_range`                                                       |

## Parts used on jobs

| Rule                                                                                                                                                                      | Where                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| An engineer records parts only on jobs they are assigned to, from the van assigned to them; the office names any location                                                 | `requireWork`, `sourceLocation` in `materials.ts` (422 `no_van`, 403 another van, 422 `location_required`)                                    |
| A use posts a `consumption` movement once per action, or becomes a conflict when stock is short — never negative stock                                                    | `recordUse` under `lockBalance`; `source_key = phone:<client action id>`; `erp_work_order_materials_client_action_unique`; 0026 balance check |
| A conflict is resolved by people: the office retries (after correcting the van, or with another quantity or place) or anyone involved cancels; a retry may conflict again | `resolveUse`; audit `work_order.part_retried`, `part_cancelled`                                                                               |
| Returning an unused part posts a `consumption_return` against the use, never more than was used                                                                           | `returnUse`; `reversal_of`; `erp_work_order_materials_returned_range` (422 `over_returned`)                                                   |
| Non-stock items and services can be recorded on a job without touching stock                                                                                              | `recordUse`: `location_id` null, cost = the item's default cost, no movement                                                                  |
| A job's parts cost is the sum of posted uses net of returns at the cost when posted, summed in SQL                                                                        | `costForJob`; shown only to seats with `inventory.move` or `purchasing.manage`                                                                |
| The phone's van stock is a forecast — the server's count less the phone's own unsent uses — and says so                                                                   | `van_stock` table on the phone, `vanStock()` in `@integr8/offline`; `vanStock` on the first pull page                                         |

## Quotes and sales orders (ADR-0006)

| Rule                                                                                                                                                            | Where                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Line and document totals are derived in SQL, never typed; discount and tax are basis points per line; gross, discount, net and tax round once to four places    | `LINE_MATH`, `documentTotals` in `sales-quotes.ts`; `addDecimals` (BigInt) for net + tax; `crm_quote_lines_discount_range`, `_tax_range`                       |
| References are `QT-000001` / `SO-000001` onwards per company, never reused, quotes and orders apart                                                             | `assign_sales_reference('quote' / 'sales_order')` locks the company's counter row                                                                              |
| An issued quote's lines and customer never change; a revision is a new draft under the same reference                                                           | trigger `crm_quote_lines_guard` (`crm_quote_lines_frozen`); `revise` clears the snapshot and the token                                                         |
| One answer per quote; an answered quote's link is spent; a revised or cancelled quote's link dies                                                               | `crm_quotes_answered_pairing`; `access_token_hash` set null on answer, revision and cancel; `crm_quotes_token_unique`                                          |
| A quote is converted exactly once, and only when accepted                                                                                                       | `lockQuote` + 409 `quote_not_accepted` / `quote_converted`; `erp_sales_orders_quote_unique`; `crm_quotes_converted_pairing` requires an answer                 |
| A confirmed order's lines never change; only what is reserved and delivered moves                                                                               | trigger `erp_sales_order_lines_guard` (`erp_sales_order_lines_frozen`)                                                                                         |
| A reservation is a promise on the line, not a movement: on-hand is never touched by confirming, reserving, cancelling or fulfilling                             | `quantity_reserved` on `erp_sales_order_lines`; no ledger write in `reserve` / `release`                                                                       |
| No location promises more than it holds: each line holds `min(due, held − reserved by every other line there)`, never below zero, under the balance lock        | `reserve` in `sales-orders.ts` (`erp_stock_lock_balance`, then one SQL update per line)                                                                        |
| Available = on hand − reserved, never shown below zero; a part used on a job sees only what is available to it (its own orders' reservations are its own)       | `availability` in `inventory.ts`; `availableForJob` in `sales-fulfilment.ts`; `recordUse` refuses beyond it as a `conflict` with `availableQuantity`           |
| A part used on a linked job delivers the order's lines for the item, oldest link first, and releases the reservation it fulfils; never more than the line asked | `consume` (per line: `take = min(remaining, quantity − fulfilled)`, `reserved = min(reserved, quantity − fulfilled)`); `erp_sales_order_lines_fulfilled_range` |
| A linked job completing delivers every line that is not stock; the order's status follows its lines; a fulfilled order holds nothing                            | `deliverOnCompletion`, `fulfilNonStockLines`, `refreshStatus` (then `release`); `erp_sales_orders_fulfilled_pairing`                                           |
| Cancelling releases everything the order held; a shortfall is `quantity − reserved − fulfilled`, flagged "to order" on the order and the inventory overview     | `cancel` → `release`; `shortLines`; `GET /v1/sales/to-order`                                                                                                   |
| The customer's token is never stored, logged or shown twice; only its SHA-256 is kept                                                                           | `mintToken` / `hashToken` in `sales-quotes.ts`; the `issue` response is the only place it appears                                                              |

## Invoices, credit notes and payments (ADR-0007)

| Rule                                                                                                                                                                                                                                             | Where                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Invoice and credit note totals are derived in SQL from their lines with the same math as quotes, never typed                                                                                                                                     | `LINE_MATH` and `documentTotals`; `erp_line_total()`, `erp_invoice_total()`, `erp_credit_note_total()` for the guards                                                                    |
| An invoice or credit note gets its number when issued, a receipt when recorded: `INV-`, `CN-`, `RC-` from 000001 per company, never reused, never changed; a discarded draft leaves no gap                                                       | `assign_finance_reference()` (security definer, locks the counter row); `finance_reference_fixed`                                                                                        |
| An issued invoice never changes, and neither do its lines; it is corrected by a credit note or, while nothing is paid or credited, voided with a reason and keeping its number                                                                   | `erp_invoices_guard` (`erp_invoices_frozen`, `erp_invoices_void_settled`); `erp_invoice_lines_guard`; `erp_invoices_issued_pairing`, `_void_pairing`                                     |
| The customer and the issuer are copied onto the invoice when issued; later changes to the customer or the settings never alter it                                                                                                                | `issue` in `finance-invoices.ts`; `customer_name`, `customer_address`, `issuer`                                                                                                          |
| Balance = total − active allocations − issued credit notes; the status shown (part paid, paid, credited) is derived from those, never stored                                                                                                     | `erp_invoice_balance()`; `invoiceStatus()` in `@integr8/core`                                                                                                                            |
| A credit note is against an issued invoice, never empty, never more than the invoice still owes, and never changes once issued                                                                                                                   | `erp_credit_notes_guard` (`_invoice_not_open`, `_empty`, `_over_balance`, `_frozen`), checked under a lock of the invoice                                                                |
| Nothing billed from an order or a job is billed twice: an order line never past what it holds (or delivered), a part used never past what was used net of returns, a job on one invoice                                                          | `lockSource` (advisory lock per order or job); `invoicedOrderQuantities`, `invoicedMaterials`; 422 `over_invoiced`, 409 `job_already_invoiced`; voided invoices release what they billed |
| A remainder that would be negative (billed in full, then on what was delivered) bills nothing                                                                                                                                                    | `isPositiveDecimal` in `finance-invoices.ts` checks the sign before comparing digits                                                                                                     |
| A receipt is recorded once and never edited or deleted                                                                                                                                                                                           | grants `select, insert`; `Idempotency-Key` required on `POST /v1/finance/payments`                                                                                                       |
| An allocation never exceeds what the receipt has left or what the invoice owes, never crosses customers or currencies, and two at once cannot spend the same money                                                                               | `erp_payment_allocations_guard` (security definer; locks the receipt and the invoice; `_over_receipt`, `_over_invoice`, `_mismatch`, `_invoice_not_open`)                                |
| A wrong allocation is taken back by stamping it removed, never deleted; the money returns to the customer's account                                                                                                                              | `erp_payment_allocations_removed_pairing`; `_frozen` allows only `removed_by/at`                                                                                                         |
| What a receipt has not allocated stays on the customer's account, per currency                                                                                                                                                                   | `customerAccount()`: owed, unallocated, net                                                                                                                                              |
| Job cost = parts at their cost when used (net of returns) + hours on site and working × the labour cost when set; profit = invoiced net − cost. Without a labour cost the figure is parts only and says so. An estimate, not an accounting entry | `GET /v1/finance/work-orders/{id}/costs`; `hoursOfMs`, `multiplyDecimals` in `@integr8/core`                                                                                             |
| A company with issued documents can still be purged; the application role cannot fake the purge                                                                                                                                                  | `integr8_purging()`; every B1 guard and the S1 line guards allow deletes only during `purge_tenant`                                                                                      |

## Assets and their history (E3)

| Rule                                                                                                                                                                                                                             | Where                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An asset is numbered `AS-000001` onwards per company when created, never reused, never changed                                                                                                                                   | `assign_asset_reference()` (security definer); `erp_assets_reference_fixed`                                                                                                                           |
| An asset is never deleted, only retired; a retired asset takes no condition, no new job and no new form                                                                                                                          | no delete grant; `erp_assets_retired_pairing`; 409 `asset_retired` in the routes and the push                                                                                                         |
| Its site is always its customer's, and moving it records where it was                                                                                                                                                            | composite FK `erp_assets_site_fk`; `relocated` event with `from_customer_id`, `from_site_id`                                                                                                          |
| A serial is unique per company, ignoring case and spaces; a tag code is unique across Integr8 and shaped like one                                                                                                                | `erp_assets_serial_unique`; `erp_assets_tag_code_unique`, `erp_assets_tag_code_shape`                                                                                                                 |
| Its history is appended and never changed                                                                                                                                                                                        | `erp_asset_events` grants `select, insert`; shape checks per kind                                                                                                                                     |
| The timeline is read, never stored: events, linked jobs, and the submissions, parts and files that name the asset or belong to a job whose only asset it is                                                                      | `assetTimeline()` and `AssetsRepository.submissionsOf` / `partsOf` / `attachmentsOf`                                                                                                                  |
| The condition shown is the one recorded latest in time, whichever device sends it first; a resent condition lands once                                                                                                           | `recordCondition` (by `occurred_at`); `erp_asset_events_client_action_unique`                                                                                                                         |
| A job's assets are at its site and in use                                                                                                                                                                                        | `POST /v1/work-orders/{id}/assets` (409 `asset_not_at_site`, `asset_retired`); the push does the same                                                                                                 |
| A form started for an asset carries only the questions its version marks, from the last submission of the same form on that asset, moved onto the version being filled; evidence, calculated and read-only questions never carry | `carryOverFor()`; `prefillAnswers(…, { only: 'marked' })`; `fieldConfigIssues` refuses `carryOver` on calculated or read-only questions; the schema refuses it on signature, photo, file and location |
| What was carried over is recorded on the draft, only with its asset                                                                                                                                                              | `submissions.carried_over`, `submissions_carried_over_shape`                                                                                                                                          |
| A warranty is `expiring` from the window's first day to its last day, `expired` after; the window is 0–365 days                                                                                                                  | `warrantyState()` in `@integr8/core`; `erp_asset_settings_alert_range`                                                                                                                                |
| The phone announces each asset and expiry date once                                                                                                                                                                              | `warrantyAlertsDue` / `markWarrantyAlerted` (`meta.warranty_alerted`), marked before it is shown                                                                                                      |

## The general ledger (A1; ADR-0009)

| Rule                                                                                                                                                                                                                                                                              | Where                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Amounts are decimal strings and `numeric(20,4)`; sums, conversions and balances are exact (BigInt ten-thousandths), never JavaScript numbers                                                                                                                                      | `toUnits`, `fromUnits`, `sumAmounts`, `journalTotals`, `convertAmount`, `naturalBalance` in `@integr8/core`                                          |
| A journal posts only when it balances on two lines or more, each line one side above zero                                                                                                                                                                                         | `erp_journals_guard` (`erp_journals_unbalanced`); line check constraints; `journalTotals` in the routes first                                        |
| A posted journal and its lines never change and are never deleted; a mistake is corrected by a reversal, once per journal, dated on or after the original                                                                                                                         | `erp_journals_frozen`, `erp_journal_lines_frozen`; unique `reversal_of`; `reverseJournal()` (409 `already_reversed`, 422 `reversal_before_original`) |
| Journals are numbered `JV-000001` onwards when posted, never reused; a discarded draft leaves no gap                                                                                                                                                                              | `assign_journal_reference()` (security definer)                                                                                                      |
| Nothing is dated before the start; nothing posts into a locked month except a year's closing journal and its reversal, on the year's last day                                                                                                                                     | `erp_journals_before_start`, `erp_journals_period_locked`, `erp_journals_closing_date` (0035)                                                        |
| A manual or opening journal is posted by a second person unless the owner allows self-approval, which the journal records                                                                                                                                                         | `erp_journals_self_approval`; `self_approved`                                                                                                        |
| An archived account takes no new postings; an account's type is fixed once posted to; the start and fiscal year are fixed once anything is posted                                                                                                                                 | `erp_journals_account_archived`; `erp_ledger_accounts_type_fixed`; `erp_ledger_settings_fixed`                                                       |
| Each document posts once: one journal per source, one queue row per source                                                                                                                                                                                                        | `erp_journals` unique source; `erp_ledger_postings_source_unique`                                                                                    |
| What a document posts has one definition, used by the automatic posting, the unposted list and the API                                                                                                                                                                            | `erp_ledger_proposal()`                                                                                                                              |
| An invoice posts receivables (with the customer) = its total, revenue = each line's net by goods or services, VAT output = total − nets; a credit note the reverse; a void the mirror of its invoice                                                                              | `erp_ledger_proposal()`; `ledger-postings.integration.test.ts`                                                                                       |
| Stock posts at the cost recorded on its movements; a movement without a cost waits for lines written by hand; transfers post nothing                                                                                                                                              | `cost_unknown`; stock branch of the proposal                                                                                                         |
| A credit note or void never posts before its invoice, and is set aside with it                                                                                                                                                                                                    | `waits_for_invoice`; `erp_ledger_try_post()`; `skipFollowing` in the routes                                                                          |
| Posting a document never blocks the document: a failure is kept on the queue row as `failed` with the database's words                                                                                                                                                            | subtransaction in `erp_ledger_try_post()`                                                                                                            |
| A document in another currency posts only at a rate someone typed, with where it came from; lines converted one by one keep their foreign amount and the rounding difference goes on the largest line, so the journal balances                                                    | `rate_required`; `convertLines()`; `erp_journals_foreign_pairing`                                                                                    |
| Reports count posted journals only and say how many drafts and waiting documents they leave out                                                                                                                                                                                   | `LedgerReportsRepository.leftOut`; `leftOut` in every report                                                                                         |
| Closing a year brings every income and expense account to zero against retained earnings on its last day and locks its months; the profit and loss leaves closing journals out, so it still shows what the year earned; the balance sheet shows earnings not yet closed in equity | `closingLines()`; `totals({ excludeClosing })`; `erp_journals_closing_accounts`                                                                      |
| A year is closed once at a time; reopening reverses the closing journal and keeps the history and the reason; a month of a closed year is not unlocked                                                                                                                            | `erp_ledger_year_closes_open_unique`, `_reopen_pairing`; 409 `year_closed` on unlock                                                                 |
| Receivables reconcile per customer: the ledger's receivables at a date against invoices issued (not voided before it), credit notes and payments before it, in the company currency                                                                                               | `receivablesByCustomer` against `receivablesAt`; the difference shown, never hidden                                                                  |

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |

## Assembly and planning (M1; ADR-0011)

| Rule                                                                                                                                                                                                                                          | Where                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| A bill version never changes; an item is never part of itself, however deep                                                                                                                                                                   | `erp_boms_frozen`, `erp_bom_components_not_itself`; `wouldContainItself` before saving |
| An order completes only if everything it takes out is available at its location after sales orders' reservations, and stock never goes negative                                                                                               | `shortage` (balances locked first); `erp_stock_balances_not_negative`                  |
| Completing twice moves stock once                                                                                                                                                                                                             | `assembly:<order>:<item>` source keys; completed orders answered as they are           |
| An assembled unit costs its parts at their average cost now, plus labour, overhead and non-stock parts, and joins the item's average cost before it arrives; a disassembled unit's cost is shared among its parts by their cost, nothing lost | `rolledUpUnitCost`, `disassemblyUnitCosts`, `applyReceiptCost`                         |
| An order's movements post once, as the order: inventory up by what the assembly adds, against assembly labour and overhead absorbed                                                                                                           | `erp_stock_movements_ledger_capture`, `erp_ledger_proposal_more` (`assembly`)          |
| A plan is a snapshot; each suggestion is drafted once                                                                                                                                                                                         | `erp_mrp_suggestions_frozen`; `already_drafted`                                        |
